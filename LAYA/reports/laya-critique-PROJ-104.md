## Acceptance Criteria
1. Scenario: Within rate limit. Given a client with a valid API key, when they send fewer than 100 requests per minute to /api/v1/search, then every request returns a 200 OK response and the response headers include X-RateLimit-Remaining with the correct count.
2. Scenario: Rate limit exceeded. Given a client who has sent 100 requests in the current 60-second sliding window, when they send the 101st request, then the API returns HTTP 429 and the response body contains a JSON object with 'error': 'rate_limit_exceeded' and 'retry_after_seconds' indicating the wait time.
3. Scenario: Rate limit resets. Given a client who received a 429 response, when they wait for the duration specified in retry_after_seconds and retry, then the request is processed normally and a 200 OK is returned.
4. Given an API key that has been revoked, when the client sends any request to any endpoint, then the API returns 401 Unauthorised with no rate-limit headers.
